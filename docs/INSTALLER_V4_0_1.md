# Інсталятор v4.0.1

Офіційне джерело: https://github.com/salenko93-hash/LiceumTVRPi5-0.18.
Використовуйте Release ZIP і його `.zip.sha256`; GitHub Source code ZIP не має
файлового manifest. v4.0.0 не змінюється.

## Windows: перевірка і встановлення

Розпакуйте пакет у нову папку. Потрібні PowerShell та Windows OpenSSH (`ssh`,
`scp`), без WSL і локального Python. На Pi потрібні Python 3, SSH і звичайний
адміністративний користувач із sudo. Замініть IP та ім'я користувача своїми.

```powershell
Get-FileHash .\LyceumTV-RPi5-v4.0.1.zip -Algorithm SHA256
# Звірте з офіційним LyceumTV-RPi5-v4.0.1.zip.sha256, потім у розпакованій папці:
.\INSTALL_AIR_RAID_RPI5.ps1 -PiHost 192.168.0.18 -PiUser admin -CheckOnly
.\INSTALL_AIR_RAID_RPI5.ps1 -PiHost 192.168.0.18 -PiUser admin
```

Встановлення запитує `INSTALL`; параметр `-Yes` призначений для вже дозволеного
адміністративного запуску. `-CheckOnly` не встановлює пакети, не створює каталоги
в `/opt`, не робить backup і не зупиняє служби. Він лише завантажує перевірені
файли у власний тимчасовий каталог, виконує читання діагностики й очищує staging.
Sudo може запросити пароль у SSH-терміналі. Паролі не передаються параметрами
команд і не записуються у журнал. Призначення логу друкується на екрані;
типово `%LOCALAPPDATA%\LyceumTV\installer-logs`. Можна задати `-LogDirectory`.
Ключі/токени в тексті помилок маскуються; конфігурація не друкується.

На самому Pi з розпакованого перевіреного пакета:

```bash
bash scripts/install_air_raid.sh 192.168.0.18 --check-only
bash scripts/install_air_raid.sh 192.168.0.18
```

## Діагностика й дозволені виправлення

Звіт JSON містить усі незалежні помилки: модель Pi 5, Linux ARM64, Debian/RPi OS,
облікові записи, тип/власника/режим каталогів, доступ від імені `lyceumtv`,
конфігурацію, версію, systemd та supervisor, Python-модулі, запас диска для
коду/backup і активну OTA. Помилка цілісності також не скасовує збір діагностики.
Відсутні залежності й службовий користувач на чистій системі позначаються WARN:
вони створюються штатним provisioning після baseline backup. Для наявної
системи це помилки, які автоматично не виправляються.

`data/ota_pending` — файл-маркер активної транзакції, **його відсутність нормальна**.
Не створюйте його вручну як каталог або порожній файл. Наявність маркера блокує
інсталяцію до завершення штатного recovery; недоступний шлях не вважається відсутнім.
Перевіряється фактичний доступ службового користувача до батьківського каталогу.

На існуючій системі можна створити тільки відсутні `data`, `data/.locks`,
`data/backups`, `data/logs`, `data/update_jobs`, `public/media` із режимом 700
і власником `lyceumtv`. Наявні шляхи не chmod/chown-яться; symlink, неправильний
власник, сторонній записуваний каталог або недоступність означають зупинку
з точним шляхом. Жодного `chmod 777`, рекурсивного chmod/chown `/opt/lyceumtv`,
підміни календаря чи перезапису робочої конфігурації.

Сторонні `.idea`, `.vscode`, `.git`, кеш Python та метадані ОС не входять у
завантаження. Невідомі файли коду/даних, змінені hash, symlink або небезпечні
шляхи блокують пакет. Це не послаблює перевірку виконуваних файлів.

## Транзакція та recovery

Порядок: manifest → діагностика → дозволена підготовка → повторна діагностика →
backup → перевірка архіву → встановлення → три успішні health-check → результат.
Паралельні інсталятори серіалізуються окремим lock у `/run`.

**Оновлення:** службовий worker перевіряє supervisor, створює приватний data backup,
перевіряє gzip/tar і SHA-256, потім готує code snapshot. Backup виконується при
працюючому сервері через штатні блокування даних. Лише supervisor зупиняє застосунок
на час заміни коду. Невдалий health-check повертає попередній код автоматично.
`data/current`, `data/default`, локальна конфігурація та `public/media` зберігаються.
Зміни systemd, nginx, користувачів або Python-залежностей при code-only upgrade
не виконуються. Якщо supervisor чи права пошкоджені, потрібен окремий розбір.

**Чиста система:** спочатку перевірений baseline у `/var/backups/lyceumtv` і snapshot
наявних системних налаштувань, потім apt, службові користувачі й нові каталоги.
Початкові ключі генеруються локально; наявні дані не переписуються. За помилки
служби зупиняються, новий код ізольовано в `failed-fresh-code-*`; дані зберігаються.
Це відкат коду, а не видалення apt-пакетів або повне повернення ОС. Для повного
відновлення ОС потрібний попередній образ диска. Не робіть автоматичне
розпакування системного snapshot поверх `/etc` без адміністративного аналізу.

Повторна чиста інсталяція дозволена лише за власним приватним маркером
`data/.installer-fresh.json`; незрозуміле непорожнє дерево без встановленого
застосунку зберігається й блокується. Після тайм-ауту транзакції спочатку перевірте
`data/update_jobs/<job>/result.json` і `journalctl -u lyceumtv`, не запускайте
інсталятор повторно поверх незавершеної OTA.

Ручний відкат попереднього code snapshot:

```bash
sudo -u lyceumtv python3 -B /opt/lyceumtv/server/official_updates.py rollback --approve
```

## Межі перевірки

Linux-тести використовують ізольовані тимчасові дерева та реальні процеси
supervisor; PowerShell-тести імітують SSH/SCP і не підключаються до Pi. Браузерні
сценарії використовують синтетичні дані та приглушений тестовий звук.
Реальні apt/systemd/HDMI/аудіо на Raspberry Pi вимагають окремого дозволу.
Невідомий текст останньої помилки попереднього запуску неможливо встановити
заочно; v4.0.1 зберігає точний етап і причину для її подальшого розбору.
